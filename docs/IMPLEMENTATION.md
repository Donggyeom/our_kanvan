실제 운영 Firebase 프로젝트/자격증명은 제공되지 않았다. 운영 배포 및 운영 데이터 삭제 없이 demo-* Emulator에서 검증한다. 운영 네트워크 지연 및 공개 URL 검증은 프로젝트 연결과 별도 배포 승인 후 가능하다.

## 보완한 동작

- 가입 직후 bootstrap/registerUser가 겹쳐도 사용자 문서를 트랜잭션으로 생성하며 소속/역할을 덮어쓰지 않는다.
- 같은 이메일·워크스페이스 초대는 결정적 문서 ID와 트랜잭션으로 중복 생성을 막는다. 토큰 원문은 응답 링크에만 있으며 DB에는 해시만 저장한다. 만료 링크 수락 시 상태를 expired로 기록하고 토큰 해시를 제거한다.
- 권한·보드 활성 상태·업무 버전 확인을 실제 쓰기와 같은 트랜잭션에서 수행한다. 이력도 함께 저장하고 단순 순서 변경은 이력에서 제외한다.
- 이동은 task version과 board orderVersion을 검증한다. 클라이언트의 숫자 위치를 신뢰하지 않고 beforeId 앵커를 기준으로 서버가 활성 업무를 정수 간격으로 재정렬한다. 다른 카드 이동/생성/상태 변경/보관·복구도 보드 순서 버전을 갱신한다.
- 필터/별도 정렬/여러 보드를 합친 내 업무에서는 드래그 정렬을 막고 상세 상태 변경을 제공한다. 드래그 시작 시의 업무·보드 버전을 고정한다. 실패한 변경을 성공처럼 낙관적으로 유지하지 않으며 충돌 시 구독을 다시 연결한다.
- 보드 구독은 문서 자체의 workspace/member 필드로 Rules 검증을 받는다. 업무/이력 쿼리는 workspaceId와 boardId로 제한한다. 보드 갱신마다 모든 업무를 재구독하지 않고 추가/제거된 보드만 처리한다.
- 다른 사용자가 편집한 업무는 상세 화면에 최신 내용 불러오기 배너를 표시하고, 사용자의 현재 초안을 자동으로 덮어쓰지 않는다. 보드 접근이 취소되면 열려 있던 상세를 닫는다.
- 담당자 선택은 현재 업무가 속한 보드를 기준으로 한다. 보드에서 팀원을 제거하기 전 활성 담당 업무의 재배정을 요구한다.
- 참여자 체크박스·보드 설명 편집, 한국어 변경 이력, 입력 레이블, 모달 Escape/포커스 복귀, 드롭 강조, 모바일 화면 넘침 및 연결 상태를 보완했다.
- Node 22 버전 고정, 잠금 파일, 검증용 CI, Hosting 보안/캐시 헤더, 복합 인덱스, 설정/검증 기록을 확인하는 배포 게이트를 추가했다.

운영 Firebase 프로젝트에서의 검증, 공개 URL 및 성능 목표 달성 여부는 별도 증거가 필요하다. 현재 증거와 차단 요인은 TEST-RESULTS.md에 기록한다.
