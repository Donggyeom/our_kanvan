# Firebase 없는 공유 서버

Node.js 서버 한 대가 계정·보드·업무·초대·변경 이력을 저장합니다. 각 브라우저는 로그인 세션을 따로 가지며 약 1초 간격으로 서버의 최신 상태를 받습니다. Coral Orange와 4열 보드는 그대로입니다. 기존 로컬 버전의 데이터는 자동 업로드하지 않습니다.

## 로컬 실행

Node.js 22와 npm이 필요합니다. Java나 Firebase 설정은 필요하지 않습니다.

```bash
npm ci
npm run build:shared
ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD='본인만 아는 10자 이상의 비밀번호' npm start
```

브라우저에서 `http://localhost:3000`으로 접속하고 지정한 이메일·비밀번호로 로그인합니다. Windows PowerShell에서는 `$env:ADMIN_EMAIL='owner@example.com'`, `$env:ADMIN_PASSWORD='...'`를 지정한 뒤 `npm start`를 실행하세요. 최초 실행 때만 초기 관리자 계정이 생성됩니다. 이후 환경 변수를 바꾸어도 기존 비밀번호는 변경되지 않습니다.

팀 설정에서 팀원 이메일을 초대하고 생성된 링크를 전달하세요. 팀원은 그 링크에서 회원가입 후 초대를 수락하면 같은 보드를 볼 수 있습니다. 초대 이메일은 자동 발송하지 않습니다. 비밀번호 재설정 메일도 제공하지 않습니다. 로그인 계정별 역할을 서버에서 검사합니다.

## Render에 배포

저장소의 `render.yaml`을 Blueprint로 불러오거나 Docker Web Service를 만드세요.

- 저장소: `Donggyeom/our_kanvan`, 브랜치: `main`
- `ADMIN_EMAIL`: 처음 사용할 관리자 이메일
- `ADMIN_PASSWORD`: 10자 이상의 강력한 비밀번호. 호스팅 서비스의 비밀 환경 변수로 입력하세요.
- Render의 기본 주소는 `RENDER_EXTERNAL_URL`로 자동 적용됩니다. 커스텀 도메인은 `PUBLIC_URL`에 정확한 HTTPS 주소를 지정하세요. 로그인 요청의 출처 검사에 사용합니다.
- 영구 디스크를 `/data`에 연결하고 `DATA_DIR=/data`로 지정하세요. 영구 디스크를 제공하는 유료 플랜이 필요합니다. 실제 가격은 Render에서 확인하세요.
- HTTPS가 켜진 상태에서 배포하세요. 운영 세션 쿠키는 Secure·HttpOnly입니다.

Render 이외의 호스팅에서는 `PUBLIC_URL`을 실제 HTTPS 주소로 설정하세요. `/healthz`가 정상이어도 요청 출처 설정이 맞아야 로그인이 됩니다. Docker 이미지는 앱과 서버를 함께 제공합니다. 정적 호스팅만으로는 사용자 간 공유가 되지 않습니다.

## 저장·운영 범위

`/data/flowboard.json`에 데이터를 보관합니다. 서버는 모든 변경을 순서대로 처리하고 임시 파일 작성·fsync·원자적 교체 후 응답합니다. 버전이 다른 카드 수정/이동은 409로 거절하고 최신 내용을 다시 불러옵니다. 초대 토큰·세션 토큰은 해시로, 비밀번호는 salt+scrypt로 저장합니다. 사이트 데이터가 지워져도 서버 데이터는 남습니다.

한 서버 프로세스와 한 영구 디스크를 사용하는 소규모 팀용 구성입니다. 여러 서버 복제본을 동시에 같은 파일에 쓰면 안 됩니다. 자동 확장은 끄고 1개 인스턴스로 운영하세요. 다중 인스턴스가 필요하면 PostgreSQL 같은 공유 DB로 전환해야 합니다. 데이터 파일에는 개인정보가 포함되므로 비공개로 백업하고 복원 시 서버를 먼저 중지하세요. 디스크를 삭제하면 데이터도 삭제됩니다.

공개 가입을 허용하지 않습니다. 가입하려면 관리자가 만든 유효한 초대 링크가 필요합니다. 계정 복구·자동 백업·메일 발송·대규모 부하 테스트는 포함하지 않습니다. 서비스 운영 전 정기 백업을 설정하세요.

검증 명령: `npm run test:shared`, `npm run check`, `npm run test:ui`.

## 이슈 채팅

Issue 상태의 카드를 열고 **이슈 채팅** 탭에서 메시지를 주고받을 수 있습니다. Enter로 전송하고 Shift+Enter로 줄바꿈합니다. 메시지는 최대 2000자이며 작성자·시간과 함께 서버에 저장됩니다. 카드당 최대 5000개입니다. 전송에 실패하면 입력 내용을 유지하고 같은 메시지를 다시 보낼 때 중복 저장을 막습니다.

해당 보드에 접근할 수 있는 팀원만 대화를 읽고 보낼 수 있습니다. 메시지를 보낼 수 있는 것은 활성 Issue 카드뿐이며 상태가 바뀌거나 보관/삭제되면 기존 대화만 읽을 수 있습니다. 대화 전송은 업무 버전을 바꾸지 않으므로 업무 편집과 별도로 처리됩니다. 기존 저장 파일은 메시지 배열이 없어도 그대로 불러옵니다. 이 기능은 Firebase 없는 공유 서버와 로컬 모드에서 제공합니다.
